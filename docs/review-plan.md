3)Критерии проверки (чек-лист)
3.1. Функциональная корректность
 Результат каждого запроса на тестовом наборе данных совпадает с эталонным расчётом: количества без расхождений, денежные суммы с точностью до 0.01
 Все JOIN имеют явные условия соединения; число строк на выходе совпадает с ожидаемым (нет дублирования из-за декартова произведения)
 Значения NULL в агрегатах по продажам и остаткам обработаны явно (COALESCE / FILTER)
3.2. Безопасность / Надёжность
 Все запросы с входными параметрами (период, магазин, категория) параметризованы, конкатенации строк нет (0 случаев)
 Отчётные запросы содержат только SELECT и выполняются под ролью с правами «только чтение»
3.3. Производительность
 Время выполнения каждого запроса по EXPLAIN (ANALYZE, BUFFERS) не превышает 5 секунд на объёме данных не меньше боевого
 В планах нет Seq Scan по таблицам больше 1 млн строк там, где можно использовать индекс; SELECT * не используется
3.4. Читаемость и стиль
 Глубина вложенности подзапросов не больше 2, остальное вынесено в CTE (WITH)
 Алиасы таблиц и столбцов осмысленные, сложные участки логики снабжены комментариями
 Файлы отформатированы согласно .editorconfig
